# SMB/Samba synchronization

In Settings, add an SMB/Samba destination, give it a name, and optionally enter a credential-free `smb://server/share` address. **Open macOS connection flow** opens the OS connection window; authentication and Keychain credentials belong to macOS. Heed neither mounts shares itself nor installs a Samba server. A running Heed menu app handles the native folder picker. Select a folder on an already mounted share, test access, and connect. A new destination requires explicit confirmation to create an empty `Heed Library` subfolder. Existing arbitrary content is never adopted as a library.

The destination header is `heed-library.json` with exactly `format: heed-portable-library`, `schemaVersion: 1`, and an immutable `destinationId` UUID. This container identity is independent of each meeting's origin library UUID. Imports retain origin identities and immutable revision ancestry across devices. Each Mac keeps its own connection names, selected paths, mount identities, private queue and native authorization bookmark. These fields are never part of portable meeting exports.

Up to eight named destinations can be retained; one is enabled at a time on this Mac. Enabling a destination pauses the previous one. Rename, disable and disconnect do not change recording settings or delete meetings. Disable retains queued publication jobs. Disconnect removes this Mac's connection configuration; local revisions remain in the portable catalog and a later connection can queue them again. There is no remote meeting deletion API.

## Mount, access and security checks

The native adapter uses public Darwin `fstatfs` to require `smbfs`, bind the selected filesystem ID and hash of the server/share mount source, and recheck descriptors during every operation. Credentials are stripped before hashing; raw mount sources, `smbutil` output and OS error strings are never included in API errors or logs. Every path component is opened relative to a retained directory descriptor with `O_NOFOLLOW`. Losing a mount or replacing it at the same path cannot create an ordinary local directory or redirect a write into the replacement. A legitimate remount can have a new filesystem ID: explicitly test and reconnect the existing destination to accept it, with the same destination UUID.

The public, scoped `smbutil statshares -m <selected mount> -f json` diagnostic reports the negotiated dialect and active protection. `SIGNING_ON` establishes active signing. `ENCRYPTION_REQUIRED` on SMB 3 establishes required share encryption. `SIGNING_SUPPORTED` and `ENCRYPTION_SUPPORTED` describe capabilities and are insufficient. SMB 1, unavailable diagnostics and unverified protection block synchronization. An encrypted connection cannot silently fall back to signing. MacOS owns session authentication; Heed tests actual access and does not independently verify a server-side user identity or store authentication secrets.

Read-only mounts and libraries with denied publication capabilities remain available for verified text import. The access probe tests fsync, atomic exclusive publication and read-back in uniquely named temporary files, then removes only those probes. A server that cannot perform the required publication primitive is not shown as upload-capable. Heed does not weaken OS or server security settings to make a connection succeed.

## Publication and recovery

The shared portable format specifies immutable content-addressed media, meeting JSON, manifests and independent per-device commit markers. The marker is published last. The adapter streams bounded data, verifies exact lengths and SHA-256, fsyncs temporary objects, and uses public `renameatx_np(RENAME_EXCL)` to publish without overwriting an existing revision. Identical retries are idempotent; conflicting immutable content fails closed. Stable connection-owned temporary names bound interrupted retry debris; only that exact connection's unfinished temporary object is reclaimed. Other devices' temporary files and all committed data are retained.

Confirmation reads back the marker, manifest, finalized transcript and every referenced audio object and verifies their hashes. This is a **share acknowledgment**, not evidence that data survives server power loss. MacOS and SMB caches, server filesystem flushing, storage controllers and server configuration define the physical durability boundary. Test server restart and power-loss durability separately for the actual deployment.

The private atomic queue is bounded to 10,000 revisions per destination. Confirmation is tracked per destination; verification on one share does not acknowledge publication to another share. Audio awaiting another destination's acknowledgment remains protected from local quota eviction. Retries use persisted exponential delays capped at one hour. Recording or other active audio work postpones background synchronization. Network failures do not prevent ordinary local transcription or AI access to already imported complete meetings.

Discovery reads committed text and metadata, never bulk audio. The portable library imports newest eligible text first under the configurable device quota, including staging, replacement copies and catalog/index costs. Text becomes locally searchable and AI-ready only after verified, complete persistence. Audio is downloaded on request. Concurrent divergent revisions remain explicit conflicts; timestamps and clock skew never choose a winner. Disconnecting or evicting cached audio does not delete remote data.

## Validation boundary

Automated tests use synthetic mount identities, temporary local fixtures, isolated HTTP servers and two independent private catalogs. They cover mount loss/replacement, no local fallback, symlink/traversal rejection, immutable collisions, bounded/corrupt transfers, read-only access, protected transport, durable queue controls, quota pressure, metadata-only discovery and explicit creation consent. The native app compiles for macOS 14 and runs address/local-folder self-tests without mounting a share or displaying a permission prompt.

Physical acceptance is still required on the MacBook Air M1 and MacBook Pro M4 Pro: a disposable Samba server and native macOS SMB share; English/Portuguese content; all four UI locales; actual folder permissions and Keychain authentication; mount replacement, sleep/wake, server restart, denied writes, disconnect during a large transfer, Unicode names, quota pressure, concurrent edits and offline AI. macOS 14 compilation does not establish actual macOS 14 SMB interoperability. No real share, account, private meeting or application installation was used in automated validation.
