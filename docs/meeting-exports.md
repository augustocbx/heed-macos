# Offline meeting exports

Open **Meetings → More options → Export PDF or subtitles…** on a finalized meeting. Choose PDF, SRT or VTT, select content, inspect the preview, generate the file, then select **Save export**. Existing plain text, Markdown and copy actions remain available.

PDF supports transcript, notes and accepted open/completed tasks in any nonempty combination. Speaker labels and timestamps are optional with transcript content. Suggested or dismissed tasks are excluded. Notes and tasks require acknowledgment of the exact preview; earlier or unknown source content requires a separate acknowledgment. Exporting does not approve, regenerate or change that content.

The preview identifies the accepted source and its local version. Before generation the server checks the current source, title and selected notes/task revisions. Changes require a fresh preview and review, including a correction followed by a revert to the same text. Once validated, the generated file retains that frozen snapshot even if the meeting changes later. Change scope or format to discard the previous preview and acknowledgments. Cancel/close terminates the owned worker; Save becomes available only after generation succeeds.

PDF uses bundled licensed Noto Sans Regular/Bold 2.015, A4 pages, 48-point margins, 11-point body text and page/source footers. English, Portuguese, French, German and their tested combining accents remain literal. Font coverage is checked for every selected scalar; unsupported glyphs, including unsupported emoji, produce a clear error directing you to UTF-8 text export. Text is not transliterated, clipped or shrunk to one page. Notes markup is printed as text; remote images are never loaded.

SRT/VTT contain transcript and existing segment times only. They require nonempty timed segments; PDF also supports untimed transcript or notes/task-only documents. Cues retain original order after stable time sorting and retain overlap. Correcting words does not estimate new word timings. Times round to milliseconds; invalid, collapsed or out-of-duration intervals fail clearly. Text wraps at 42 graphemes, retaining combining characters; repeated blank lines become one line boundary. Long/dense cues and overlap have visible warnings. Literal markup, entities and timing arrows are escaped so decoded words do not create extra cues. Playback support for overlapping cues varies by player.

All generation runs locally in a dedicated browser worker. PDF code/fonts are bundled and loaded only when needed; the interface uses its system font fallback without remote font requests. No provider, cloud upload, account or key is required. Selected snapshot/request content is bounded at 16,000,000 UTF-8 bytes, and PDFs at 2,000 pages. Size failures remain retryable with a smaller scope.

Downloads contain only the chosen accepted content and provenance. They exclude recordings, file paths, credentials, embeddings, internal diagnostics, recovery history and retranscription candidates. They are ordinary browser downloads outside Heed's managed library: deleting a meeting or changing retention does not delete previously downloaded files.

Developer verification: build the interface, run `node scripts/qa/meeting-exports.mjs --output /private/tmp/heed-export-artifacts`, then `python scripts/qa/verify-meeting-exports.py --input /private/tmp/heed-export-artifacts --render /private/tmp/heed-export-rendered` with pypdf 6.1.3 and Poppler installed in an isolated QA environment. Existing Chrome is used on macOS; otherwise install the pinned Playwright Chromium. Inspect every rendered page and the four narrow-dialog screenshots. All fixtures are public authored synthetic content; output stays outside the repository and the runner shuts down only its owned server/browser/data.
