# Correct and recover a saved transcript

Saved, finalized meetings have one accepted transcript. Corrections change that source, so meeting search, text/Markdown export and citation input see the confirmed text. Live preview remains provisional. Editing text preserves segment times, channels, speaker attribution and recording files; renaming a speaker remains a separate action.

Edit a segment, review the draft and save it explicitly. A meeting without timed segments supports whole-text correction. Empty text is valid. Draft text is rendered literally, including multiline content and accents. Text editing does not seek audio; the separate playback controls retain their original timestamps. Meetings without retained audio can still be corrected and recovered.

Find and replace uses literal text within each segment or whole-text target. Choose case sensitivity and whole-word matching, request the preview, inspect its count/before-and-after text, then confirm the displayed changes. It does not interpret regular expressions or match across segment boundaries. Changing any option invalidates that preview. Accents remain meaningful, Unicode word boundaries are respected, and CRLF is normalized to LF. No-match and cancelled previews leave the accepted source unchanged.

Each accepted change is saved atomically with a recoverable journal and a monotonically increasing local transcript version. A second tab with an older hash or version cannot overwrite a newer change. Edit→revert may restore the same text hash, but the local version still prevents an old tab or derived job from passing its guard. A conflict retains the draft for explicit reload, copy or discard; a failed/quota-limited save does not acknowledge an unsaved correction. Retried request IDs are idempotent and cannot be reused for different commands.

The history distinguishes the current generation, earlier accepted generations and text actions. Original text and earlier corrected text remain recoverable. Legacy meetings establish their baseline when this feature first adopts the saved source; that baseline is not represented as a recording-time original. An inverse applies only when its targets remain compatible with the current generation and later edits. Unrelated speaker renames are preserved. When an inverse is incompatible, recover the earlier text explicitly rather than silently replacing a newer source.

Retranscription of a saved meeting produces a durable candidate. The accepted transcript, its corrections and derived jobs remain unchanged while the candidate is staged or discarded. Compare the current and candidate source, then explicitly replace or discard. Replacement checks the original candidate base plus the current source hash/version, archives the previous generation and retains the original audio paths. A candidate whose base changed cannot replace a newer correction. Failed acceptance preserves the candidate for retry. Starting retranscription requires available retained audio; reviewing an existing candidate does not require another inference run.

Earlier notes, task evidence and chat citations retain their original provenance and become stale when their source changes. Legacy notes without verifiable provenance stay explicitly unknown/stale; they are never relabeled as freshly generated for the current text. Returning to an earlier hash does not make an earlier automatic job fresh. Only a successfully persisted accepted change supersedes an obsolete source-bound notes worker; failed writes leave its ownership intact.

Portable schema version 2 preserves accepted generations, correction history and verifiable source identity. Import creates the receiver's own local version. Pending candidates, local request receipts, private paths, embeddings and local diagnostics are excluded. Schema version 1 remains readable and its export format remains compatible; it cannot carry the new recovery history. An irrecoverable older notes source is preserved as explicitly unverified provenance, rather than asserted current.

Recovery state has explicit limits: accepted portable state is at most 16,000,000 bytes; there are at most two pending candidates, each at most 16,000,000 bytes; candidate request receipts are bounded at 1,000 with reserved terminal slots. A correction command is bounded to 1,000,000 UTF-8 bytes and 1,000 targets. History is not silently pruned when a limit or managed storage quota is reached. Resolve the reported limit before retrying; recordings and previously accepted text remain preserved.

The interface supports English, Brazilian Portuguese, French and German. These interface locales do not translate user-authored transcript content or select the speech recognition language. Implementation and runtime evidence are recorded in [the issue 7 QA report](qa/issue-7-transcript-corrections.md).
