# Service conflict notices

Heed diagnoses the configured API, interface and transcription listeners using the existing service identity and checkout/process ownership checks. A listening socket alone never establishes readiness. Read-only diagnostics expose only the service role, port, state and an optional sanitized executable basename. They never expose process arguments, identifiers, working directories, environment values or private paths.

The states are ready, stopped, starting, unhealthy, conflict and unavailable. Starting requires a live checkout-owned bootstrap checkpoint and expires after 35 seconds. Failed startup becomes unhealthy instead of waiting indefinitely. Startup checkpoints match each service port independently, so an API proxy override does not hide the interface or transcription startup state. An unidentified or unrelated listening service is a conflict. Inspection failures are unavailable, without raw exceptions. Separately managed IPv6 targets do not borrow an unrelated IPv4 listener or its application name. Locally managed localhost listeners still require checkout ownership. Diagnostic results are cached for five seconds; Check again bypasses the cache. Helper processes have bounded runtime/output and are supervised; Vite closes its owned diagnostic helpers on shutdown. Native output reads remain bounded even if the helper exits while an unverified descendant retains stdout: diagnostics becomes unavailable, preserves that descendant and remains usable for subsequent checks.

The interface can diagnose API conflicts through its own same-origin route. Vite diagnoses the actual validated API proxy destination, including an explicit override. The browser does not request health from a conflicting API and removes stale transcription/CPU profiles when the transcription listener is unavailable. Unknown inspection shows a check-unavailable notice and does not add a recording readiness gate; recording continues to use its existing fresh coordinator authority. The native menu permits unknown diagnostics only with a fresh identity-verified controller response that allows starting. A conflict replaces the generic transcription repair suggestion. The native menu uses the same local helper when both web services are down, shows service/port/application details, offers a recheck and retries the existing ownership-safe startup. Neither diagnosis nor retry terminates an unrelated listener.

Users can stop the conflicting application themselves or configure a free allowed Heed port and restart. Device-local `service-ports.json` supplies saved ports unless explicit environment settings override them. API, interface and transcription ports must be distinct and outside 3000–3999, 5000–5999, 7000–7999 and 8000–8999. Installed bundle and LaunchAgent settings must match; if they still override the saved values, rerun the installer while idle with matching `HEED_API_PORT`, `HEED_UI_PORT` and `HEED_TRANSCRIPTION_PORT` settings. The notice performs no installation or automatic port migration. English, Brazilian Portuguese, French and German messages share the same behavior.

## Validation

- Python tests exercise actual unrelated HTML/JSON/nonresponsive listeners, ready/stopped/starting/unhealthy distinctions, safe names, bounded private state, startup expiry, cached inspection and explicit recovery. Runtime regressions preserve rollback safety and narrowly recognize exact Bun server entries with documented watch/hot flags while rejecting other paths, working directories and flags. Framework Python entries are recognized by exact script/cwd checks; an ownership-inspection failure during rollback does not abandon other verified children.
- Actual isolated API and Node-run Vite tests exercise hostile origins and Host headers, a foreign transcription profile, an explicit foreign API proxy destination and recovery without terminating the listener.
- Interface tests exercise four locales, safe service/port/application rendering, recheck, distinct failure states and removal of stale working profiles.
- Native self-tests exercise public-payload validation, localization, bounded nofollow saved-port reads, environment precedence, existing identity-protected transport and cleanup of an oversized helper plus its freshly verified private process subtree. Build-only validation does not install or access a real account.
- Disposable source-only helper/native CLI fixtures ran on the M1 and M4: unrelated HTML/JSON and nonresponsive listeners were conflicts, all other listeners were preserved, public output contained only permitted fields, and closing fixtures produced stopped states. These tests do not claim installed-app upgrades, actual capture, ASR or model acceptance.

The implementation deliberately omits a general port manager, process termination, model download and service installation flow.
