# Local service ports and readiness

The canonical defaults are in `config/service-ports.json`: API **48100**, interface **48101**, transcription **48102**. All bind to loopback. Existing Ollama remains at **11434**. Heed rejects service and QA ports in **3000–3999**, **5000–5999**, **7000–7999** and **8000–8999**, and rejects invalid or overlapping service ports before startup.

The installer atomically saves validated device preferences in `~/.heed-app/service-ports.json` (or `HEED_APP_DIR`), with mode 0600. Env-less native browser hosts, lifecycle tools, Python services and Bun/Vite consume that bounded regular file. It contains only port numbers and a format version; it is excluded from portable synchronization. Invalid, oversized, linked or corrupt preferences fail closed and are preserved for repair. Explicit environment values override saved ports; saved ports override canonical defaults.

Configure `HEED_API_PORT`, `HEED_UI_PORT` and `HEED_TRANSCRIPTION_PORT` together before installation or startup. The API retains `PORT` as a legacy alias; contradictory API values fail. The installer validates and stores the resolved values for both LaunchAgent and Finder launches. Vite binds its exact configured port without an automatic fallback. `VITE_API_BASE` remains an explicit safe loopback API origin; the normal interface uses the API proxy.

`HEED_TRANSCRIPTION_URL` takes precedence for API requests to a separately managed local sidecar. It must be a loopback origin with an allowed port, without credentials, paths or queries. When its target differs from the configured local sidecar, bootstrap verifies that external service and does not start another sidecar silently. Set `HEED_TRANSCRIPTION_PORT` for a sidecar launched from this checkout. An updated Heed identity is required; legacy model flags alone are not readiness.

The API keeps private checkout/PID metadata on its origin-guarded identity and desktop-status routes; the public model-health response retains its existing fields. API and interface expose `/.well-known/heed-service`; transcription includes the same service identity in `/health`. Readiness checks the service name, protocol version, checkout path and positive PID. Model loading is a separate condition: a healthy sidecar may still report `ready:false`. Native and browser clients preserve their existing capture/permission behavior after service verification.

Bootstrap refuses an unrelated target listener with a technical diagnostic and does not terminate it. Upgrade restart validates every target before stopping anything, checks the active-meeting status, and stops only matching commands with checkout-owned working directories. Former ports are inspected only to retire positively identified checkout-owned legacy processes; foreign listeners are preserved. Uncertain identity, changed ownership or active capture fails closed. Broader translated conflict notifications are tracked in [#59](https://github.com/augustocbx/heed-macos/issues/59).

Existing libraries, recordings, preferences and credentials are not migrated by this port change. Physical installation/readiness on both Macs remains an acceptance step after the reviewed PR and exact-head CI pass.
