# OneDrive implementation plan

Status: approved implementation sequence, following completion of #26 integration. Dependencies #25, #26 and #27 provide the destination registry, portable transaction service and shared quota before adapter integration. Validation uses synthetic OAuth/HTTP fixtures without real account connections or private uploads.

1. Verify the proposed design against live issue #29 and resolve the account/scope compatibility gate. Add synthetic eligibility tests before enabling any account type. Do not substitute full-drive permissions silently when app-folder discovery, delta or upload sessions fail.
2. Run a native MSAL packaging spike with a pinned supported release, registered public-client configuration and isolated Keychain doubles. Cover cancellation, account selection, refresh serialization, unavailable Keychain, disconnect and reauthorization. Add no real account or registration during automated work.
3. Implement bounded Graph transport and strict portable-path/item-ID mapping. RED tests cover response caps, authority/ancestry changes, shortcuts, immutable create collisions, ETags and redacted error reporting.
4. Implement durable paginated delta generations and quota-aware checkpoints. RED tests cover duplicate IDs across pages, invalid continuation loops, 410 rescan, partial scans, journal faults, remote deletion observations and restart without dropping pending imports.
5. Implement resumable immutable publication and streaming verification. RED tests cover aligned sequential fragments, expiry, 416/status recovery, lost final response, unavailable SHA-256, source mutation, marker-last ordering and two-device divergent revisions.
6. Wire the provider registry and four-locale settings without bypassing #26/#27. Cover selected-library eligibility, initial import, lazy audio, read-only/auth/local-quota/remote-quota states, offline AI use and disconnect while work is active.
7. Run repository CI, independent whole-feature QA and acceptance review. Authorized synthetic-account/device validation must prove every claimed account configuration; keep unsupported/manual criteria open and publish exact validation limits. Real account connection or deployment remains outside automated validation.
