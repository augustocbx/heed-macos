# Menu-driven release updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Discover stable releases and safely upgrade Heed through the macOS menu, preserving data and guiding users through renewed permissions when necessary.

**Architecture:** Swift owns responsive menu controls and delegates bounded discovery and installation to a trusted Python helper. A detached coordinator persists transaction state outside versioned runtimes and shares locking and durable backend maintenance with the existing release installer. Fresh build-specific permission reports separate installation success from authorization and actual capture acceptance.

**Tech Stack:** Swift/AppKit/Foundation, Python 3.9 standard library, Bash, Bun/TypeScript, existing GitHub release manifest schema 1.

**Spec:** `docs/superpowers/specs/2026-10-06-issue-61-menu-updates-design.md`

## Global Constraints

- Supported installation targets remain Apple Silicon Macs running macOS 14 or later.
- Check automatically at startup and every 24 hours; checking never installs an update automatically.
- Repository content and technical logs remain English. Interface translations support English, Brazilian Portuguese, French and German with English fallback.
- Preserve recordings, transcripts, speaker names, settings, models, scoped bookmarks, Keychain contents and private connection state.
- Verify both installer and payload byte sizes and SHA-256 before execution or extraction. Reject drafts, prereleases and older/equal targets.
- Block installation and component restarts while recording, saving, transcription or other processing is active. Retry requires explicit user action.
- Use `--no-permission-prompt` for menu updates. Never reset privacy permissions automatically or use `tccutil reset` as an update step.
- API 48100, interface 48101 and transcription 48102 are the defaults; preserve valid configured overrides. Never use ranges 3000–3999, 5000–5999, 7000–7999 or 8000–8999 for issue validation. Shared Ollama 11434 is not restarted.
- Implement and validate in `.claude/worktrees/issue-61`, branch `feat/issue-61-menu-updates`. Preserve unrelated checkouts, services and dirty files. Never add `Co-Authored-By`.

## Review Focus

1. Backend restart between replacement and verification must not admit automatic capture or queued work (Task 2).
2. Coordinator death or PID reuse must not produce a false success or let a retry overlap a surviving installer (Tasks 3–4).
3. macOS reporting granted permissions while capture is blocked must still leave accessible signature-renewal guidance (Task 5).
4. A larger release version published earlier must win over a newer publication with a lower version; incomplete pagination cannot mean up to date (Task 1).
5. A hand-edited transaction path, archive link or service configuration must not overwrite data or control unrelated services (Tasks 1, 3–4).
