# Issue #69: bounded, scope-safe local meeting retrieval

This specification implements the approved lexical-first direction for [issue #69](https://github.com/augustocbx/heed-macos/issues/69). The documentation base is `298bc324f1b6f7d9764572ca786f57983715de4e`. Product implementation must first integrate completed [issue #7](2026-10-06-issue-7-transcript-corrections.md), including its accepted-source persistence and portable contracts; the #7 document lives on its issue branch until integration. This document authorizes no change to an unfinished #7 task.

## Outcome and boundaries

Individual and scoped library chat find relevant accepted transcript evidence through a disposable local lexical index, rather than repeatedly sending up to 80 uniformly sampled batches to a model. Retrieval remains useful without embeddings, a cloud service or a new resident process. Exact source-bound citations, language behavior, schema validation, history isolation, cancellation and recording preemption remain intact.

Index current finalized `Session.transcript` and `Session.segments[].text`, using #7's canonical accepted source. Exclude drafts, retranscription candidates, recognition history, old edit text, generated notes, chat answers, tasks, audio and voice embeddings. Empty accepted text is valid but supplies no evidence. Source revision remains the existing content hash; local transcriptVersion protects ongoing work against edit/revert ABA. Neither the index nor its versions cross devices through portable storage.

This issue does not redesign chat, change the ASR or chat model, add synchronization transports, enable remote inference or claim complete semantic recall. New coverage/status strings preserve English, Brazilian Portuguese, French and German. Future consumers #72/#73 can use the retriever interface; their features are outside this delivery.

## Storage and lexical contract

Use `bun:sqlite`, with no new production dependency. A scoped in-memory capability probe on Bun 1.4.2 / SQLite 3.54.0 confirmed FTS5, `unicode61 remove_diacritics 2` and `fts5vocab(..., instance)`; `Ação São João` produced `acao`, `sao`, `joao`. These are observed development capabilities, not proof for every packaged runtime. Add a startup capability check; unavailable SQLite/FTS disables indexing and selects the bounded fallback.

Use an in-memory, one-chunk scratch FTS5 table only to obtain token terms/frequencies. Tokenize queries identically. Persist direct SQLite postings with composite key `(sessionId, sourceRevision, term, evidenceOrdinal)` and indexed lookup on that prefix. Persist a source manifest and chunk metadata/evidence ID, exact quote, speaker, timestamps and original segment/paragraph index. Scratch text is removed after each chunk. Stored quotes remain exact; search accent folding never rewrites canonical text or citations. Do not introduce stemming, transliteration, stopword lists or neural normalization in the first ranker.

Reuse `transcriptEvidence`'s revision-qualified IDs and 1,200 UTF-16-unit splitting initially; extract a lazy iterator with identical output to avoid allocating every chunk during indexing. Split units and offsets remain compatible with existing citations. Version tokenizer/chunker/ranker separately. A schema or tokenizer/chunker change requires a new index generation; a ranker change invalidates only retrieval caches.

Store generations under `APP_DIR/library/indexes/retrieval/`, registered with ManagedQuota's existing `indexes` category. Files/directories are private (0600/0700). The portable artifact schema and publication manifests exclude this directory. Source JSON is authoritative. Do not export index databases or private derived quotes in benchmark evidence.

## Scope before lookup and scoring

Resolve scope using authoritative current metadata, normalized tag keys and existing any/all semantics. A single-meeting question selects only that meeting; library chat preserves its exact selected snapshot. An empty label selection remains empty. The source catalog must be ready and validate the request snapshot before any retrieval cache or posting lookup. Discovery-incomplete catalog state queues the chat with a retrieval readiness reason; it cannot fabricate a complete selection count.

For each eligible `(sessionId, sourceRevision, transcriptVersion)`, query only that exact source's postings and manifests. The SQL access path uses the composite scoped key; no unrestricted FTS MATCH, database-wide BM25, global document-frequency weighting or global top-k followed by filtering is allowed. Candidate ranking, neighbor expansion and optional reranking receive only eligible current sources. Tests must show that adding, changing or deleting excluded content cannot change eligible IDs, scores, order, query coverage or cache reuse. Global disk exhaustion can change index readiness; report that resource condition separately, never as an eligible ranking signal.

The initial score is scope-independent and deterministic: `100 * distinctMatchedTerms + sum(min(termFrequency, 3))`. Exact ties use binary session ID then evidence ordinal. Read each query term's postings through source-qualified keyset pages, then merge at most 64 ordered term streams by evidence ordinal; this computes a complete candidate score without scanning every nonmatching chunk or using an unbounded SQL GROUP BY/sort. Keep 48 global best hits and the best hit from each of the 16 highest-scoring matching sources in bounded heaps, deduplicating their union to at most 64 candidates; limits encountered during enumeration make lookup partial. This source allocation prevents one meeting's high-scoring repetitions from eliminating every other matching source before diversity selection. Take protected source winners in score order, then fill remaining slots globally, up to 16 anchor hits. Add at most one predecessor and one successor per anchor, only within the same eligible source/revision, deduplicate by evidence ID, and cap the final selection at 32 excerpts. Anchors precede neighbors when the cap binds. This diversity policy is fixed and benchmarked rather than described as optimal. Excluded meetings cannot influence it.

Query text keeps the existing 2,000-character limit and adds an 8,000-UTF-8-byte limit before tokenization. Reject invalid scalar/NUL input. Retain at most 64 distinct terms; reject overflow instead of silently changing the question. A punctuation-only/no-term question uses the bounded fallback and declares its limited strategy; an index miss with valid terms returns no retrieved evidence and never silently switches to library-wide model scanning.

## Accepted-source catalog and incremental consistency

Add a narrow post-commit observer at #7's SessionTags boundary, used by successful source commits, metadata saves, deletion and committed tag transactions. Notify after durable persistence and before successful API acknowledgment. The observer synchronously updates a text-free catalog descriptor containing identity, title/tags, finalized/nonempty state, source hash, local version and evidence count; it schedules indexing without doing SQL/model work in the source commit. It must not turn a successful source commit into a false failed save. Observer failure makes the catalog unavailable until reconciliation; queries queue rather than trust older metadata. Failed source/tag transactions publish no uncommitted state; recovery resolves its journal before discovery or notifications.

Source commits queue revision replacement; candidate stage/discard and metadata-only notes writes do not retokenize. Tag/title changes update the snapshot/catalog and invalidate affected scope caches without reindexing text. Deletion synchronously removes catalog eligibility and invalidates affected caches, then queues derived cleanup. Portable initial import, accepted conflict replacement and restart recovery go through the same boundary. Explicitly audit #7's final writer inventory rather than attaching route-specific hooks.

Startup discovers source metadata in bounded consecutive idle slices, one source JSON per slice, yielding and rechecking admission between slices without a 30-second delay. A chat waiting only for catalog readiness does not block this discovery; mandatory capture/processing and already running inference do. Do not stretch initial discovery across the periodic reconciliation timer. Stat and enforce a 64-MiB raw local Session file limit before parsing; local candidates/history mean this bound differs from #7's 16,000,000-byte accepted portable projection. An oversized/unreadable source makes full catalog discovery unavailable with an actionable error, not an invented label selection. Build the text-free catalog completely before admitting scope queries. Periodic external reconciliation is triggered every 30 seconds, then processes changed identities in the same bounded yielding idle slices; it catches missed notifications/import recovery. Supported mutations pass through the single server-owned boundary; arbitrary external edits during a running query are outside that ownership contract and are caught on reconciliation or materialization. Immediately before indexing or materializing evidence, reread authoritative source and compare both hash and local version. Reject an obsolete indexing result; compare again after generation and before saving the answer.

Replace a source's old manifest/chunks/postings transactionally. A manifest records total evidence count, indexed evidence count, indexed-prefix boundary and exact revision/version/configuration. A quota/chunk limit may publish a truthful partial prefix atomically. No partially written source is queryable. Old source rows may remain temporarily on disk but are ineligible immediately after the source commit. Deletion/correction cleanup and canceled-source staging receive priority over new indexing, keeping growth bounded.

## Resource, recovery and fallback limits

Defaults below are conservative engineering limits, not measured hardware optima. A typed internal policy accepts smaller values in tests; production configuration cannot exceed these hard bounds without a reviewed change.

| Resource | Hard bound / behavior |
|---|---|
| Source catalog | 20,000 descriptors; a larger library disables this retriever with explicit capacity status rather than silently omitting meetings. Existing source storage stays usable. |
| Index generation | 64 MiB SQLite main file, 250,000 evidence rows, 2,000,000 posting rows; first reached cap stops growth and marks omitted evidence. |
| Disk during generation work | 192 MiB maximum across active/staged databases and rollback journals; reserve through ManagedQuota before writes. No WAL; `journal_mode=DELETE`, `temp_store=MEMORY`, 4 MiB SQLite page cache, mmap disabled. Account for all sidecars and release reservations only after cleanup. |
| Index work | One raw source file at a time, at most 64 MiB; at most 128 evidence rows per slice; yield and check abort/busy between slices. Index only current accepted fields; do not treat accepted-projection bounds as raw local-record bounds. |
| Query work | One query at a time; 100,000 matching rows, 250 ms retrieval work budget, pages of 128 matching rows with abort/busy/deadline checks; 64-hit heap; no full matching result materialization. |
| Retrieval cache | LRU of 32 entries, at most 1 MiB total serialized values, 60-second TTL; IDs/scores/coverage only, no answer or quote copies. |
| Fallback | At most 4 current selected sources, 256 evidence excerpts and 64 MiB cumulative raw source JSON bytes, deterministic binary session-ID/evidence order. Lexical score the examined prefix; declare omissions. At least one bounded source remains usable if an index cannot be allocated. |
| Model input | At most 4 generation requests; existing 8,192-token context and 5,500-byte serialized input cap per request remain mandatory. Budget complete JSON including question/history/IDs/escaping; never cut citation text to force a fit. |

Reuse the existing processingMaintenance/audio/notes/tasks/chat scheduler admission and waiting reasons. Background index work runs only while mandatory processing, recording/finalization and pending chat are absent. Retrieval stops at page boundaries when preempted; generation retains the existing controller/attempt/source guards. Do not add a parallel memory governor or run maintenance in a chat's pending slot. Query-time stale/missing index uses the fallback; it never waits on a rebuild that its own pending state prevents.

Use bounded transactions and DELETE rollback journals so transient disk usage is reservable. Reserve capacity for a source transaction before changing SQLite; enforce `max_page_count` and row limits; roll back on FULL/write errors. A schema rebuild stages a new database, verifies manifest/configuration and fsyncs files, then atomically publishes a small active-generation pointer through atomic JSON. Reserve old + new + worst-case staging journal before starting; if quota cannot fit, retain old compatible data or use fallback. After pointer publication, retire old files only when no reader uses them. Exactly one active and one staged generation may exist. On interruption, pointer-selected committed data remains active; cleanup only unreferenced owned staging files, release their reservations, then resume/restart. Corruption disables the disposable generation and rebuilds without deleting accepted transcripts. Never promise secure erasure.

Fallback materialization is itself scope/revision/version checked. A single oversized source beyond the allowed source-record bound is skipped with a resource omission; source data remains intact. For a partially indexed source, begin fallback at its first unindexed evidence ordinal rather than rereading an already searched prefix. For missing/stale sources begin at ordinal zero. Deduplicate indexed/fallback counts by source/evidence identity. No-term fallback examines a bounded prefix independently because no lexical index query ran. Do not say that fallback examined the entire scope unless its counters prove it did.

## Cache and citation contracts

Cache keys include normalized tokens (or no-term fallback query), selected source IDs/hash/version, scope fingerprint, generation ID, selected-source manifest epoch and tokenizer/chunker/ranker policy. Source replacement inside the same generation changes its selected-source manifest epoch and invalidates cached coverage/results; excluded-source replacements do not. Optional experimental model identity is not shared with production caches. Resolve and validate scope before lookup; repeat guards on cache hits, before materialization, before/after each generation await and at answer commit. A metadata-only source title change affects the library snapshot; version changes invalidate ABA reuse even when text hashes recur.

Materialize selected evidence from authoritative accepted source, not blindly from stored quotes. Require exact ID, revision, quote and location agreement. A mismatch invalidates the cached/indexed source and causes a bounded retry against a fresh matching request snapshot or a source/scope conflict; never silently answer an obsolete request. Only evidence supplied in the current request's generation batches can validate citations. Existing unknown/forged evidence rejection, timestamp navigation, untrusted-input treatment and strict structured-answer completion stay mandatory. History may resolve language/follow-up references but supplies no factual evidence.

## Honest coverage and user messages

Add optional versioned retrieval coverage to ChatCoverage, leaving old stored turns readable. Distinguish selected meetings/evidence, currently indexed meetings/evidence, searched meetings/evidence, lexical matched rows, selected retrieved excerpts, excerpts actually sent to generation, and cited meetings/excerpts. Counts are unique in their own units; searched means the strategy looked up those sources/evidence, not that the LLM read them. In a complete indexed lookup, searchedEvidence is the number of eligible indexed excerpts whose postings were covered, including nonmatches. When enumeration/deadline caps bind, searchedEvidence is null because the exact covered excerpt count is not known; report matchingRowsVisited and lookupComplete=false instead. Fallback knows its examined-prefix count.

Use `indexComplete`, `lookupComplete`, `generationComplete`, `partialReasons` and a strategy discriminator, not one overloaded completeness flag. Carry omissions caused by missing/stale/partial indexes, fallback, query budget, context/model-call caps and unavailable/capacity catalog state. A full lexical lookup does not prove semantic completeness. For new retrieval turns, legacy `complete` is always false; `reviewedChunks` counts generation batches and `totalChunks` counts planned batches, while versioned coverage controls the new UI. Old turns retain their previous rendering.

New no-support text always says no supporting evidence was found in the searched/retrieved excerpts. Never claim absence in the entire meeting/library from lexical retrieval, fallback or partial generation. Display selected/searched/retrieved/cited meeting counts, supplied excerpt count and specific partial reasons. A zero-hit full lexical lookup is a valid empty answer with zero generator calls, not a transcript-empty error. Keep contradictory commitments, rejected proposals and later tentative updates distinct; rank order cannot establish that a later statement supersedes an earlier commitment.

## Grounded evaluation and optional embeddings

Provide deterministic authored synthetic EN/PT fixtures with exact expected evidence IDs, plus literal accents/names, paraphrases, contradictory commitments, tentative/rejected decisions, dated updates, unanswered queries, any/all tags and excluded-only answers. Put answer-bearing facts between the old 80-sample positions. Scale a seeded library to 1, 100 and 1,000 meetings and exercise the index cap. Fixture provenance and expected IDs are public; personal transcripts are never QA artifacts.

Measure old sampling, lexical retrieval and one actual optional local embedding/hybrid experiment on the same questions: recall@8/@16, evidence/source precision, zero-result/no-answer behavior, PT/EN breakdown, indexing throughput, cold/warm retrieval and model latency, process peak RSS and disk/model bytes. Separate lexical recall from generated factual correctness. Use real embeddings; fake scalar/vector fixtures test plumbing only and cannot support quality conclusions.

Prefer an already cached licensed multilingual model. Otherwise an explicit isolated QA command may download pinned `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` files into a separate QA cache, after displaying model identity/license/estimated bytes. Its [official model card](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2) describes Apache-2.0 licensing, multilingual sentence embeddings and a 128-token input limit. Pin revision and record file digests before use; benchmark token-window splitting rather than silently truncating 1,200-character excerpts. Create a disposable QA environment; never mutate the installed Heed venv or enable a cloud inference provider. Loading is local-only, `trust_remote_code=false`, with network disabled after explicit download. Bound model artifacts to 1 GiB, QA embedding memory/RSS to 2 GiB and run one CPU worker with batch size 8; abort and record cap failures. Experimental vectors are scope/revision-qualified and stay in private temporary QA storage.

Report actual recall and resource gains/losses on available M1 Air and M4 Pro hardware, with missing runs explicit. This issue delivers the lexical path and measured evaluation; production embeddings/reranking remain off unless a later reviewed change selects them from evidence. An optional experiment that fails its resource budget is a measured outcome, not a reason to silently fetch a larger model. No model download/loading occurs at app startup, normal chat, indexing, test execution or default installation.
