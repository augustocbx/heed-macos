# Google Drive connector design

Implementation is explicitly authorized; real account authorization, private uploads, and two-Mac acceptance remain user-operated. The connector uses the portable storage and managed-quota foundations without replacing local SessionTags. Completed local transcripts remain available offline; media is fetched only by an explicit request.

A device-specific connection chooses a registered Desktop OAuth client ID and one access mode: app-authorized libraries (`drive.file`), existing-library import (`drive.readonly`), or existing-library publication (`drive`). The last two show an explicit explanation and require consent before starting authorization. Per-file access cannot promise arbitrary existing-library descendants. A shared library created/authorized for the same OAuth application can use the narrow mode across installations; arbitrary existing libraries need the documented wider mode. OAuth client registration, API enablement, and any Google verification/organization policy remain distribution prerequisites. No client secret is embedded. Authorization uses the system browser, S256 PKCE, a random loopback port and one-use state. Cancellation/timeout closes the listener. Refresh/access tokens and resumable session URLs live only in macOS Keychain through a separate Security-framework helper; JSON config holds opaque references and public IDs. Disconnect preserves local transcripts and pending jobs; optional revoke is explicit.

Folder selection reads stable folder ID, type, capabilities and shared-drive context. Eligible library identity is a versioned marker; newly created libraries are initialized explicitly. Provider operations map portable paths to stable Drive IDs and selected-library public Drive properties. Duplicate paths, outside-library parents, shortcuts, incomplete search, changed immutable contents, and insufficient permissions fail closed. Pagination is bounded. Initial discovery scans commit markers; incremental changes stage candidate checkpoints and metadata until PortableLibrary validates all referenced artifacts and durably saves its catalog, then acknowledgeDiscovery commits the checkpoint. Expired tokens trigger bounded reconciliation. Account-wide change entries outside the selected library are ignored and never downloaded.

Uploads use predetermined stable file IDs, durable job state and resumable status probes. Source length/SHA-256 is verified before publication; chunks are bounded and session URLs are opaque vault entries. A restart probes provider progress, expired sessions restart on the same reserved file ID, and retries never create uncontrolled duplicate artifacts. Immutable revisions preserve both device branches independently of provider revision retention. Required objects and manifest are confirmed before a commit marker can be published. Provider acknowledgment is distinct from SHA-256 verification; missing SHA-256 requires bounded download/hash verification, never re-labeling MD5 as SHA-256. Faults protect local pending copies. No cache eviction or disconnect deletes remote objects. Connector mutations carry the expected connection ID, folder ID and durable generation; stale tabs fail with 409. A central mutation lease blocks competing provider operations across asynchronous credential and folder changes.

Settings adds four-locale connection, permission, library selection/create, capacity and disconnect controls alongside existing quota-aware import/publication. Local managed usage, Drive capacity, and unmanaged Drive-desktop cache are distinct. Synthetic OAuth listeners, fake Keychain bridges and disposable provider HTTP fixtures test rejection, refresh, pagination/checkpoint commit, upload restart/expiry, collisions/integrity, shared permissions, capacity/rate limits and offline state. Native helper compiles for macOS 14+ with a no-Keychain self-test. Real account quality and Air M1/Pro M4 Pro acceptance remain documented pending checks.
