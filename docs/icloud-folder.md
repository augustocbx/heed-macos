# iCloud document folder connector

The connector uses a folder chosen by the user through the macOS folder picker. No private account is connected by installation, tests or startup. It does not use CloudKit, an app-owned ubiquitous container, private framework APIs or an embedded Apple credential. Real-account acceptance remains a separate gate.

## Public macOS APIs and distribution boundary

The helper targets macOS 14.0 on the build machine's architecture. It uses AppKit `NSOpenPanel`, Foundation security-scoped bookmarks, `FileManager.ubiquityIdentityToken`, `NSFileCoordinator`, `startDownloadingUbiquitousItem`, URL ubiquitous-item resource keys, and `NSMetadataQuery` scoped to the selected folder. These public APIs predate the macOS 14 deployment target. The opaque account token is archived privately with its public NSCoding contract and compared with the current token. It never enters portable artifacts, HTTP snapshots, process arguments or diagnostic logs.

The current local installation is ad hoc signed. The helper is built in the checkout and copied into the app resources; it does not install an iCloud entitlement, alter provisioning, register a ubiquitous container or connect a production account. A selected document folder differs from an app-owned ubiquitous container. Packaging/signing, renewed bookmark access and availability of the account token must be validated in the actual distribution on both supported Macs. Successful compilation and synthetic self-tests do not prove production iCloud access. No App Store-only requirement is asserted.

Primary references: [NSFileCoordinator](https://developer.apple.com/documentation/foundation/nsfilecoordinator), [security-scoped access](https://developer.apple.com/documentation/foundation/url/startaccessingsecurityscopedresource()), [ubiquity account token](https://developer.apple.com/documentation/foundation/filemanager/ubiquityidentitytoken), [uploaded status key](https://developer.apple.com/documentation/foundation/urlresourcekey/ubiquitousitemisuploadedkey), [metadata query scope](https://developer.apple.com/documentation/foundation/nsmetadataquery/searchscopes), and [iCloud file status](https://support.apple.com/guide/mac-help/check-icloud-drive-file-folder-status-mac-mchlc994344b/mac).

## Explicit connection and local visibility

Choose an existing Heed library folder or confirm initialization of a new empty folder. The header identifies the destination independently of the origin library identities in immutable meeting revisions. Device-local configuration retains the bookmark and account binding; exported meeting metadata excludes them.

Preview verifies committed manifests and transcript hashes, reports eligible counts and bytes, and does not make a remote preview visible to AI. Import requires the current reviewed preview and reserves managed local space through the common library before staging and writing complete authoritative sessions. Audio downloads are separate and lazy. Missing files or unhydrated placeholders leave the operation pending; corrupt or partial revisions never become complete meetings. Signed-out/changed accounts, stale bookmarks, unavailable folders, symlinks and changed destination headers reject access instead of creating a replacement local directory.

The native helper coordinates individual artifacts and their staging paths, rather than relying on a root directory lock to cover children. Descriptor-relative no-follow access retains the selected root identity. Account/root checks run during transfer and before publication. Stable per-owner/hash locks remain held through temporary-file cleanup; interrupted retries reuse bounded stage names. Header creation uses its own stable lock and bounded pending descriptor. Unknown staging content is preserved for repair.

## Publication and verification limitation

For a v2 library, the common library admits the canonical manifest and durable pending intent first, transfers immutable audio objects and the meeting payload next, and publishes the complete commit marker last. Legacy v1 libraries retain audio and payload before the manifest, with the commit marker last. Incomplete artifacts never become complete discovery or local AI sources. Shared-audio garbage collection remains disabled. Private state distinguishes saved, staging, publication pending and errors. Native observations distinguish pending upload, system-reported uploaded, cloud-full (Foundation error 4354), server unavailable (4355) and other provider errors. Account-unavailable (signed-out or disabled), account-changed, bookmark-stale, folder-unavailable, permission-denied and hydration-pending failures carry a small sanitized issue enum into the settings UI. Unknown failures use generic recovery guidance. This enum is distinct from the numeric Foundation provider observation error code. Bounded stderr envelopes are parsed only after failed control/write operations; streamed artifact bytes never carry diagnostic envelopes. File eligibility/hydration failures are actionable errors; the helper does not treat an old uploaded flag as success after an error.

`ubiquitousItemIsUploaded` means the system reports upload; it is not a server-side checksum receipt or independent second-device verification. The adapter always returns `local-only`. A locally readable file, successful immutable write, and system-reported uploaded flag cannot mark the source revision remotely verified or release its sole private pending audio. An independent second-device import must verify exact artifacts during real acceptance. Automatic release based on iCloud status remains gated pending a separately approved verification mechanism.

Status observations use scoped asynchronous metadata-query notifications and a bounded run-loop deadline. They occur outside coordinated read accessors. Polling upload status while holding a coordinated read can prevent the provider's own work, so that pattern is deliberately excluded.

## Quota, retry and disconnect policy

The default local managed budget is 2 GB and remains user-configurable. Complete local transcripts, private catalog metadata, downloaded media and Heed staging belong to that budget. iCloud/Finder-managed external folder caches and cloud account quota do not. Cleanup never deletes iCloud library files to reclaim private cache space.

Starting recording or transcription aborts optional library transfers and waits for their cleanup before audio work proceeds. New transfer work is rejected while that cancellation drains; credential/configuration mutations keep their exclusive transaction lease. Optional transfers pause while recording/processing is active. Pending job journals survive restart and explicit retries reuse revisions and immutable paths. The pending queue is capped at 10,000 revisions; exponential retry deadlines are bounded. This first connector uses explicit preview, import and publication actions. It does not start an unattended account session. If protected data fills the local quota, increase the configured limit or pause optional transfers; retained text and pending source audio are preserved. Native child processes have cancellation and bounded deadlines; account changes cannot produce a successful transfer acknowledgment.

Pause/disconnect removes future synchronization access and the provider selection. Disconnect removes the stored folder binding while keeping imported local transcripts and recoverable private pending jobs. It does not sign out of macOS, remove another app's iCloud access, delete remote history, or infer deletions from an outage. Explicit local meeting deletion suppresses automatic resurrection through the common private tombstone.

## Validation and remaining gates

Synthetic tests cover native child-file coordination, account-change interruption before rename, a competing second-process stage lock after rename, no-follow paths, immutable conflicts, corrupt/truncated input, bounded discovery, native status serialization, upload-state versus checksum boundaries, reviewed origin-guarded controls and all four interface locales. Each of the three critical concurrency protections was removed in a separately compiled temporary mutant and the corresponding self-test failed. Two isolated real portable catalogs with the adapter test committed transcript import without audio, lazy audio integrity, concurrent corrections, quota pressure and preservation of pending first-device media. These fixtures do not use an Apple account.

Still required: consented iCloud folders and both actual Macs; cloud-only placeholders, delayed uploads, sleep/wake, offline transfer, actual account sign-out/change, cloud-full and eligibility failures, packaged bookmark permissions, independent round-trip integrity, English/Portuguese meetings, and all four UI locales. Keep this issue open until those applicable acceptance criteria are evidenced. No real-account or production capability is enabled by the research/QA run.

Configuration changes hold the shared exclusive mutation lease across asynchronous native/account work. If provider preference activation fails, the connector restores its previous private binding and selection; an unsuccessful rollback leaves synchronization unavailable for recovery. A device-local transition journal retains both bindings and the previous provider preference before either changes. It is cleared only after commit or complete rollback. An unresolved intent blocks connector initialization after restart and preserves local media for recovery. All publication/import/disconnect controls carry the connection ID the user reviewed. A stale tab receives a conflict response rather than acting on a replacement folder. The common portable-library API likewise requires the reviewed provider ID for remote operations.
